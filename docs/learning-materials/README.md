# 嵌入式系統學習材料：從軟體工程師到 Bare-metal 開發者

## 概述
本套學習材料專為具備高階語言背景（C#、Python、Web/API 經驗）的軟體工程師設計，協助你進入「無 OS 微處理器（Bare-metal MCU）」的世界。

## 核心理念
- **穩定運行**：系統必須在最壞情況下仍能安全運作
- **低資源**：有效利用有限的記憶體與 CPU 資源
- **Non-OS/Bare-metal**：無作業系統，直接控制硬體

## 實踐案例
**日本熱水瓶智慧化改造**

透過 ESP32 (Bare-metal 模式) 實現：
- GPIO 模擬按鈕控制
- ADC 讀取 NTC 溫度計
- FSM (狀態機) 控制加熱邏輯
- ESP32 無線通訊 (MQTT/TCP)
- 硬體保護機制（看門狗、防抖動）

### [01. 概念對應表：硬體術語 vs 軟體開發概念](./01-concept-mapping.md)

### [02. 第一階段：物理抽象與 I/O 控制](./02-phase1-io-control.md)
學習如何安全地控制實體硬體，並解決硬體特有的訊號品質問題。

**核心知識點**：
- GPIO 的電氣特性（Push-Pull vs Open-Drain）
- 機械按鈕的彈跳問題（硬體防抖 + 軟體防抖）
- 繼電器控制與安全機制
- 實作練習：
  - 安全的按鈕模擬器
  - 帶保護機制的繼電器控制
  - 完整的按鈕輸入處理（短按、長按、連擊）

**軟體工程師的硬體坑**：
- 使用 `delay()` 阻塞迴圈
- 忘記防抖動機制
- 繼電器驅動不足
- 未考慮電磁干擾

---

### [03. 第二階段：資料獲取與轉換](./03-phase2-adc-sensing.md)
掌握 ADC 原理，學會從雜訊中提取有效訊號，並將電壓轉換為物理量。

**核心知識點**：
- ADC 基礎原理（取樣、量化、精度）
- NTC 熱敏電阻溫度量測（Steinhart-Hart 方程式）
- 雜訊抑制與濾波技術（移動平均、中位數、複合濾波）
- ADC 校正與精度提升
- 實作練習：
  - 基礎 ADC 讀取與溫度轉換
  - 異常偵測與保護
  - 進階濾波與異常值剔除

**軟體工程師的硬體坑**：
- ADC 讀值不穩定
- 未使用濾波導致跳變
- 忽略量化誤差與 EMI 雜訊
- 校正參數不精確

---

### [04. 第三階段：系統架構設計](./04-phase3-fsm-architecture.md)
掌握 Super Loop + FSM 架構，取代多執行緒思維，實現穩定的 Bare-metal 系統。

**核心知識點**：
- 從多執行緒到 Super Loop 的思維轉換
- Super Loop 設計原則（非阻塞式設計）
- 有限狀態機 (FSM) 設計與實作
- 任務排程器設計（時間片輪詢）
- 狀態持久化與恢復
- 實作練習：
  - 熱水瓶狀態機（IDLE、HEATING、KEEP_WARM、FAULT）
  - 優先級任務調度
  - 狀態持久化與斷電恢復

**軟體工程師的硬體坑**：
- 狀態轉換時忘記更新硬體
- 保溫邏輯導致繼電器頻繁切換
- 缺少超時保護
- 異常恢復條件過於寬鬆

---

### [05. 第四階段：穩定性工程](./05-phase4-stability.md)
學習看門狗定時器與硬體級別的安全保護，建立多層次防護機制。

**核心知識點**：
- Watchdog Timer 原理與實作
- 條件式餵狗（智能看門狗）
- 中斷服務程式 (ISR) 與緊急保護
- 多層次安全架構（軟體→中斷→看門狗→硬體熔斷）
- 異常記錄與診斷（黑盒子系統）
- 實作練習：
  - 看門狗保護系統
  - 硬體中斷安全系統（緊急停止、傾倒感測器）
  - 黑盒子診斷系統

**軟體工程師的硬體坑**：
- 無條件餵狗失去保護意義
- 在 ISR 中進行複雜操作
- 黑盒子資料未持久化
- 看門狗超時設置不當

## 硬體平台

### 建議配置
- **主控板**：ESP32-DevKitC（或相容板）
- **感測器**：NTC 熱敏電阻（10kΩ，Beta = 3950）
- **執行器**：繼電器模組（5V，光耦隔離）
- **安全元件**：
  - 緊急停止按鈕
  - 傾倒感測器（水銀開關或滾珠開關）
- **輔助元件**：
  - LED 指示燈
  - 電阻、電容（防抖、濾波）
  - 飛輪二極體（繼電器保護）

### 開發工具
- **IDE**：ESP-IDF + VSCode（或 Arduino IDE）
- **除錯工具**：
  - 序列埠監視器
  - 邏輯分析儀（選配，用於 GPIO 波形分析）
  - 萬用電表（必備）
- **測試工具**：
  - MQTT 客戶端（MQTT Explorer、mosquitto_pub）
  - HTTP 客戶端（Postman、curl）

## 核心價值主張

### 為什麼選擇 Bare-metal 開發？
```
有 OS (如 FreeRTOS)          無 OS (Bare-metal)
─────────────────────────────────────────────
✓ 多執行緒抽象               ✓ 零系統開銷
✓ 豐富的中介軟體             ✓ 完全可預測性
✗ 記憶體開銷大（每 Thread）  ✓ 極低記憶體佔用
✗ Context Switch 延遲        ✓ 即時反應能力
✗ 除錯複雜（Race Condition） ✓ 除錯簡單（線性流程）
```

### 適用場景
- **物聯網裝置**：長期穩定運行、資源受限
- **工業控制**：即時性要求、可靠性第一
- **消費電子**：成本敏感、功耗要求
- **安全關鍵系統**：可預測性、可驗證性

## 總結

從軟體工程師到嵌入式開發者，不是學會新的語法，而是建立新的思維模式：

- 從「假設輸入正確」到「驗證一切」
- 從「快速開發」到「穩健設計」
- 從「功能實現」到「異常處理」
- 從「相信軟體」到「依賴硬體」

**硬體開發的本質**：讓系統在最壞情況下也不會出事。
